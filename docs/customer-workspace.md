# 用户工作台、多市场模拟盘与商业化设计

日期：2026-10-13。本文区分已实现的内测基础版和后续产品规划；本地代码实现不代表已部署到公网。

## 产品方向与入口

把 AlphaPilot 从个人自部署的 A 股 AI 交易员，逐步扩展为「用户拥有独立模拟账户、选择规则策略、持续观察执行证据」的服务。

- `/`：原有公开只读演示，继续展示原单账户 AI 交易员；原控制接口的生产隔离不变。
- `/workspace/`：注册登录、账户总览、收益表现、模拟交易、我的策略、套餐与用量、账号安全。
- `/api/workspace/*`：必须登录的账户与策略 API。登录成功不授予原有系统控制权限。

中文优先，保留英文标的名称；可在浅色、深色和跟随系统之间切换，支持手机。
界面参考 [Composer](https://www.composer.trade/) 的策略启用流程和 [QuantConnect](https://www.quantconnect.com/) 的研究、账户、持仓和订单组织方式（2026-10-12 读取官网）。
展示真实现金、持仓、成交、费用和执行原因；缺少估值时显示不可用，净值曲线只来自实际采集的快照。

## 当前已实现

### 身份与隔离

邮箱/密码注册、登录、注销、7 天绝对过期的可撤销会话。密码 12–128 字符，使用标准库 scrypt 加随机盐；会话使用随机令牌且只存摘要。
Cookie 为 HttpOnly、SameSite=Lax，生产 Secure。登录态写请求必须校验同源及 `X-CSRF-Token`。
注册和登录有持久化防爆破限制；工作台按服务端用户 ID 独立限制每分钟 120 次读、30 次写，超限返回 429 与 Retry-After。注销仍可执行。

账户、资金、持仓、委托、策略均经服务端用户身份定位，不接收客户端 user_id 或初始资金。
每个市场只允许一个免费模拟账户，上限三个，每个账户初始资金固定为 100,000 对应计价货币。
新账本位于独立 SQLite，不读取或复制原 `paper_account.json` 的个人资产。用户被停用后，会话和模拟订单均拒绝，后台任务跳过其策略。

第二阶段已加入邮箱验证、找回密码、修改密码、登录会话列表、单会话注销和注销其他会话。
生产默认要求验证邮箱后开户、提交委托或启用自动策略；未验证用户仍可查看已有数据、导出记录和暂停策略。
同一规则在 API、账户写事务和后台策略任务执行，不能靠绕过前端解除。
开发默认不要求验证；可显式配置 `ALPHAPILOT_REQUIRE_VERIFIED_EMAIL`，生产不建议关闭。

验证链接有效 24 小时，重置链接 30 分钟，令牌仅保留哈希且绑定用途与凭据版本。
同用途重发使旧链接失效；修改/重置密码原子失效全部旧会话与操作链接。网页读取链接 fragment 后立即移除，只在用户点击确认时消费，不把令牌存入浏览器持久存储。
邮件发件域名只从显式 HTTPS `ALPHAPILOT_WORKSPACE_ORIGIN` 构造，不信任请求 Host。

邮件默认关闭。显式开启 `ALPHAPILOT_MAIL_ENABLED=true` 并配置 SMTP 后，用户点击才会触发发送，注册不自动发邮件。
验证邮件同步等待投递结果，安全中心显示已发送/失败/过期；密码恢复统一返回「已受理」，避免暴露邮箱是否注册。
密码恢复邮件使用进程内 BackgroundTasks；进程退出可能丢失待投递任务，不能把 202 当成送达。待投递任务最多保留 120 秒的发送资格，用户可重新申请；不持久存储明文令牌用于自动重发。
MFA、账号注销/数据删除和邀请制尚未实现，当前仍定位受控内测。`ALPHAPILOT_ALLOW_REGISTRATION=false` 可关闭新注册，已有用户仍可登录。

### 多市场账本

| 项目 | A 股 ETF | 美股 ETF | 加密现货 |
| --- | --- | --- | --- |
| 白名单 | 510300、510500、159915、588000 | SPY、QQQ、IWM、DIA、TLT、GLD | BTC-USD、ETH-USD |
| 计价货币 | CNY | USD | USD |
| 数量 | 100 份整数倍 | 1 股整数倍 | 平台 1e-8 步长，叠加数据源产品精度和最小金额 |
| 时段 | 上海交易日，含午休 | 纽约常规时段，处理夏令时、节假日及提前收盘 | 全天 |
| 卖出限制 | 新买入份额 T+1 | 可当日卖出；卖出资金下一 NYSE 交易日开盘才能再次使用 | 即时 |
| 行情 | 既有 A 股源 | Alpaca IEX 数据 | Coinbase Exchange 公开行情 |
| 自动策略 | 新工作台暂未开放；原 AI 系统独立保留 | MA20/50 趋势跟随 | MA20/50 趋势跟随 |

当前仅做现金多头模拟，无做空、杠杆、期权、期货、永续合约、充值、提现或真实交易所下单。
不同币种不做未经汇率换算的资产加总。新账户也不会自动继承原有 A 股模型、LLM 记忆或研究池。

模拟订单使用服务端获取的有效报价，现金使用 Decimal，不信任客户端成交价。按买卖盘及滑点模拟市价全额成交，尚未模拟盘口容量与部分成交。
报价过期、缺失、未来时间戳、非交易时段、精度或资金不足都会阻断；订单成功前重新检查时效。
跨数据源与本机的时钟偏差仅允许 1 秒，保留原始时间并返回 `clock_skew_seconds`；超过容差仍拒绝。
行情新鲜度仍分别要求 A 股不超过 300 秒、美股 60 秒、加密 30 秒，没有用抓取时间替代行情时间。
订单请求必须携带 request_id：相同委托重试复用原成交，不再扣款；同一标识改变委托内容返回冲突。
现金、持仓批次、订单与资金流水在同一事务内提交，支持并发请求下的余额保护。

模拟费率以 `/markets` 返回为准：A 股 ETF 万三/最低 5 元、免印花税；美股万五/最低 0.01 美元；加密 0.6%/最低 0.01 美元。
滑点分别 0.05%、0.05%、0.1%。这些是研究假设，不代表券商或交易所实际收费。
美股现金账户采用保守 T+1 再使用模型；尚未实现分红、拆股对持仓账本的自动调整、汇率收益、税务及全部券商限制。历史美股信号使用拆股调整日线，但不因此宣称持仓公司行动已经处理。

### 可解释规则策略

规则为已完成日线 MA20 高于 MA50 时建仓或补至仓位上限，否则卖出该标的现有可卖持仓。
仓位上限可配置 1%–20%，UI 提供 10%/20%；每个账户一个策略，每根完成日线最多一次调整。
至少需要 50 根连续、最新且已收盘的日线。缺失、陈旧、未来或未收盘的数据不会生成委托。
回撤按账户净值相对策略历史高水位计算，达到 10% 时停止整套自动策略，并保留暂停原因；不会自动强制平仓，用户仍需检查持仓。
暂停和恢复不会清空风险基线，风险触发后不允许通过重复开关绕过暂停。

独立执行器使用账户租约防止重复 worker 同时成交，用户在计算期间暂停会取消后续委托；任务在成交后崩溃时能恢复已有订单，不重复扣款。
网页读取 worker 心跳和最近评估原因；开启策略只表示授权，独立执行器未运行时明确等待。
配置版本新增不可变留档，记录标的、仓位、回撤上限、启停和修改时间。首次观察到的旧配置标记为 observed_existing，不补造过去版本。
保存相同配置不增加版本，也不清除已处理日线；改标的前必须处理原策略持仓，暂停也不能绕过。
建立风险基准时再次检查账户流水版本与行情时效，避免在网络/数据库等待后使用已经失效的估值。
当前策略是确定性规则模板，不宣称已迁移原有 LLM 自主交易闭环到多用户服务。

### 净值证据与导出

开户时的资金基线在同一事务内写入。新建净值观察器 `services.workspace_observer` 默认每 60 秒巡检，按账户默认每 300 秒采样，独立于交易执行器，未启用策略的账户也能积累净值。
调度按最久未采样账户优先，每批最多 100 个；同一时间槽使用数据库领取记录去重，成功或失败都按间隔限流。
采样期间不持有写锁，所有持仓行情齐全且资金/持仓/流水未变化才写入，拿锁后还会重新检查行情时效。
旧账户从首次真实采样开始，不以当前持仓回填历史。缺行情或账户变动会记录失败原因，曲线断线；只持有现金的账户可以记录真实现金净值，但缺失的基准仍为空。

累计收益以初始资金为基准；最大回撤是已观测快照的峰值回撤，不代表每个盘中时刻的最大回撤。
CN/US/CRYPTO 的默认基准分别为 510300、SPY、BTC-USD，按同批有效行情第一次配对同时归一账户和基准。
「收益与基准」比较区间可能晚于开户时间，与终身累计收益分开说明。基准为价格收益，不含分红再投资；不把历史回测当作模拟账户表现。
观察器未运行时显示等待采样服务；休市或供应商缺失时可能没有有效新报价，当前不自动回填收盘估值。

成交和净值 CSV 是登录态下载，按账户所有者过滤、禁止缓存、使用 UTF-8 BOM 与 Decimal 文本。
用户可写文本防表格公式注入；单次最多 100,000 行，超限明确拒绝而非截断。收益页面每页最多 2,000 个真实点，汇总基于完整已留存序列。

## 本地运行和验证

使用项目虚拟环境安装 `requirements.txt`；新增日历依赖 `exchange_calendars>=4.11,<5` 和 `tzdata`。
所有验证应使用同一解释器。Windows 示例：

```powershell
$env:BROKER_MODE = 'paper'
$env:ALPHAPILOT_WORKSPACE_ENABLED = '1'
$env:ALPHAPILOT_WORKSPACE_ORIGIN = 'http://127.0.0.1:8000'
python -m uvicorn web.server:app --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/workspace/`。非 localhost 的身份写入要求 HTTPS；生产会话要求 HTTPS。
自动策略需要另外启动一个进程，不能把网页进程存活当作策略已运行：

```powershell
python -m services.workspace_runner --interval 60
# 只执行一轮，仍仅模拟盘；会消费已启用策略
python -m services.workspace_runner --once
# 独立采集所有到期账户净值，不执行买卖
python -m services.workspace_observer --interval 60
# 同样支持 --once；单账户采样频率默认由以下配置控制
# ALPHAPILOT_PERFORMANCE_INTERVAL_SECONDS=300
```

邮件需明确配置：`ALPHAPILOT_MAIL_ENABLED=true`、`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM` 和 HTTPS `ALPHAPILOT_WORKSPACE_ORIGIN`。
`SMTP_TLS_MODE=starttls`（通常 587）或 `ssl`（通常 465），强制验证证书，不支持明文降级。
`/auth/capabilities` 只验证配置是否完整，不证明 SMTP 可达；无配置时界面明确不可用。凭据不写入代码、日志、导出文件或前端。

美股需在服务端配置 `ALPACA_DATA_KEY_ID`、`ALPACA_DATA_SECRET_KEY`，只请求固定市场数据域名，不请求交易接口。
未配置时明确不可用，不回退到生成行情。Coinbase 公共行情不需要用户交易密钥，但服务所在地需能访问该域名。
对外服务前应确认所选行情套餐允许对应的显示和分发方式；IEX 不代表全美综合行情。

```text
python tests/test_workspace_identity.py
python tests/test_workspace_markets.py
python tests/test_workspace_accounts.py
python tests/test_workspace_api.py
python tests/test_workspace_recovery.py
python tests/test_workspace_performance.py
python tests/test_workspace_lifecycle.py
python tests/test_web_public_dashboard.py
# 安装了本地 Playwright/Chromium 时，运行真实 API + mock 邮箱/行情的浏览器验收
```

以上测试使用临时数据库及 mock 行情，不调用付费 API、不使用现有个人资金、不等于线上多用户或外部提供商验收。

本次另外执行了本地浏览器与真实身份/账本 API 的联合检查（成交行情使用隔离 fixture），覆盖注册、模拟下单、持仓、策略、退出、缺失美股配置、深浅主题和 1440/1024/375 宽度。
只读公共接口检查取得 Coinbase BTC 报价及 80 根已完成日线；未使用美股真实凭据，未验收外部美股行情或线上策略运行。

## 生产上线与回退

生产默认 `ALPHAPILOT_WORKSPACE_ENABLED=0`。网站代码发布后需显式设置为 1 才挂载用户 API，原只读演示继续可用。
生产运行 `ALPHAPILOT_ENV=production`、`BROKER_MODE=paper`，设置真实 HTTPS `ALPHAPILOT_WORKSPACE_ORIGIN`。
后端仅向受信反向代理开放，正确限定转发头信任；不要开放可绕过 HTTPS 的公网后端端口。
多域名部署时 CORS 只列明确来源，推荐 UI 与 API 同源。密码与会话接口不能被代理缓存，应用已设置 no-store。

运行账户应只拥有独立账本目录的必要权限；使用 SQLite 在线 backup API 或停服务备份，不复制一个正在写的孤立主文件。
首版定位单机受控内测，不支持多个机器同时挂载 SQLite。扩大规模后应将用户账本迁移到 PostgreSQL，并建立任务队列、按租户资源预算和集中行情缓存。

第二阶段会幂等新增凭据版本、公开会话 ID、一次性操作令牌、净值及采样记录、策略版本表。先备份，再升级；不改写原个人模拟盘。
上线验证顺序：备份 -> 部署依赖和代码 -> HTTPS 注册/邮件验证/改密/会话撤销 -> 两个用户越权验证 -> 对应行情实测 -> 小额模拟成交及资金流水核对 -> 单独启动策略 worker 和净值 observer -> 策略心跳/暂停/恢复与净值缺测检查。
回退时关闭工作台开关并单独停止新 worker 和 observer，保留新数据库与备份；不删除或迁移原有个人模拟盘。
上线、重启、生产配置修改和外部支付配置需要单独的发布操作；本次本地实现没有执行这些动作。

## 收费服务设计（规划，尚未实施）

当前数据库只允许服务端分配 free 权益，`/billing` 从数据库返回真实账户数、启用策略数和 UTC 自然月已成交订单数（重试不重复计数）；不是估算付费金额。
前端显示实际用量；没有结账、自动续费、价格或虚假升级成功。
已确定国内用户优先，首批支付渠道为微信支付、支付宝，套餐以人民币计价；具体支付产品与商户配置在接入阶段确认。
商业化围绕研究资源与工具收费。服务费账单与模拟盘资金完全分离：人民币购买的是软件服务，不能转入 CNY/USD 模拟账户，也不能从模拟账户扣除或提现。

| 套餐方向 | 目标用户 | 建议差异 |
| --- | --- | --- |
| Free | 首次体验 | 当前三市场各一账户、基础规则策略、交易明细、净值/回撤与基准比较、CSV 导出 |
| Research | 经常研究的个人 | 更多独立账户、更多策略模板、更长历史保留与批量研究能力 |
| Pro | 深度研究者 | 参数实验、受控回测预算、可追溯 AI 复盘、更多并发任务 |

具体价格要先统计每活跃用户的行情授权、LLM、回测计算和存储成本，再确定；当前不编造价格或收益承诺。
计量维度包括账户数、启用策略数、每月研究计算时间、LLM 用量与保留期，不按前端隐藏按钮实现权限。

### 国内支付首版方案

推荐按月/年一次性购买使用期、到期主动续费，首版不签约自动代扣。购买页展示人民币含税价格、权益、有效期及退款规则；具体价格与规则发布前确定。
有效期使用日历月/年，月末无对应日期时落到当月最后一天，统一北京时间展示、UTC 存储。
未到期同套餐续费从已有到期日顺延，到期后从确认支付成功时间起算；同套餐未完成订单复用，已付订单再次回调不重复延长。
不同档位间的即时升级、折算与降级留待规则明确后实现，首版不对已付款权益做隐含折价或替换。

| 使用场景 | 微信支付方向 | 支付宝方向 |
| --- | --- | --- |
| 桌面网站 | Native 扫码支付 | 电脑网站支付 |
| 手机浏览器 | 获批后使用 H5 支付 | 手机网站支付 |
| 微信内打开 | 配套账号与授权条件满足后接 JSAPI | 展示在支持的外部浏览器继续支付的指引 |

以上为产品选型方向，实际以运营主体已开通产品和接入时官方文档为准；未配置或未开通的渠道不可展示为可用。
使用对应官方接口或官方推荐实现，不建立统一代收钱包。浏览器只提交服务端允许的套餐、周期与渠道，金额与用户归属由服务端确定。

最小流程：创建本地订单及价格/权益快照 -> 向指定渠道申请支付 -> 用户完成支付 -> 服务端验证通知或主动查单 -> 原子授予权益 -> 页面展示确认结果。
关闭页面或返回成功页都不能直接改变权益；支付结果暂未知时显示待确认，由查单与对账补全。
后续数据模型建议：plans、plan_prices、plan_entitlements、billing_orders、payment_attempts、billing_events、membership_periods、refunds、usage_records、invoice_requests。
服务费金额以人民币整数分存储，账单货币固定 CNY；外部交易号按渠道唯一，本地订单号全局唯一，支付尝试保留关联与最终事实。

微信通知验签及解密、支付宝通知验签分别由渠道适配器处理，并校验商户/应用标识、订单号、交易号、金额、币种或该产品固定币种契约、支付状态。
通知事件与授予权益须幂等，订单确认与使用期写入同一事务；遇到重放、乱序、通知丢失或关单/支付竞态，先查单核实，不能仅按本地超时丢弃已付款结果。
状态分开记录：订单 pending/paid/closed、退款 pending/succeeded/failed、服务权益 active/expired；退款成功后才按已公布规则调整相应权益，绝不删除历史模拟账本。
到期保留读取和导出，暂停超额策略前清楚告知；已有持仓继续可查看、手动模拟卖出，避免把风险退出操作锁在付费门槛后。

正式接入时需要运营主体对应商户/应用、已开通支付产品、HTTPS 回调域名、签名证书/密钥，以及套餐价格、退款与开票规则。
证书/密钥仅放服务端配置，不经聊天、前端或仓库传递；现阶段只确认方案，没有创建商户订单、收款、发票或退款。

公开收费前仍需补齐：SMTP 真实送达验收、可靠邮件任务恢复、MFA、隐私和使用条款/同意版本、账户删除、支付退款/账单流程、行情分发许可确认、账本备份恢复演练与告警。
