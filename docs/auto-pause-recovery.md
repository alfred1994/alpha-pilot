# 自动交易暂停与恢复检查

盘中扫描、救援扫描和轻量看盘的耗时工作在单个工作线程执行，调度线程
继续按原 `AUTO_STOP_INTERVAL` 执行真实止损巡检。扫描阶段和预算保持可见，
止损仅在实际检查成功或暂停跳过后更新，行情失败仍告警并阻断后续计划执行。
扫描与成交分开：止损与普通/救援交易执行使用同一进程内互斥锁，外层单实例锁
仍保护独立 CLI 和 Doctor 入口。扫描线程结束前不会释放外层锁。

盘中扫描、执行及止损时效扣除当日 11:30～13:00 午休；上午的正常记录
不会仅因午休导致下午开盘立即告警，扣除午休后的真实停滞仍按原阈值处理。

首轮盘中扫描尚未完成时，首次模拟执行需要等待该扫描。Watchdog 仅在
当天尚无扫描和执行记录、当前阶段为 `scan`、且仍在代码规定的扫描预算内时
允许等待。扫描超预算、扫描已完成但未执行、后续执行停滞及止损巡检超时
仍按原有规则告警。

Doctor 解除自己的暂停后，允许等待下一轮立即启动的首次扫描完成。扫描须在
恢复后的一个循环间隔加 30 秒内启动，且未完成任何恢复后的扫描或执行；
该等待仍受扫描预算限制，不能反复用于后续扫描，也不豁免止损超时。

交易暂停期间，止损入口返回 `skipped` 和跳过原因，禁止访问交易通道。
循环只刷新暂停监控心跳，将阶段事件记为 `skipped`，不将跳过冒充实际巡检，
也不产生循环故障。如果巡检期间刚收到暂停，本轮后续看盘、扫描、交易执行
均跳过；人工暂停不会自动解除。

Linux 自动重启任务只在 Watchdog 返回非零，且存在标为 `CRITICAL` 或 `WARN`
的自动盘锁、自动循环新鲜度或自动盯盘状态检查项时重启 Auto 服务。正常检查项
或其他业务异常中的同名文字不会触发重启；其他严重异常仍由 Doctor 处理。

## 更新与验证

上线前运行自动交易、控制、Watchdog、Doctor、驾驶员契约、公共仪表盘、
Linux 任务脚本测试及编译检查。更新 `scheduler/linux_tasks.py` 后，应重新生成
并检查 `restart_auto.sh`；仅更新 Python 源码不会改变已安装的重启脚本。

部署前备份将更新的源码和已生成脚本，并保留控制状态和历史事件。部署和服务
重启须由操作员授权。更新后检查：

- `BROKER_MODE=paper`，自动循环与锁心跳更新。
- 暂停循环无新增失败事件，止损阶段为 `skipped`，真实交易动作未执行。
- 原故障被健康循环覆盖后，Watchdog 不再将它作为未恢复故障。
- Doctor 只在故障解除后恢复其自身暂停；人工暂停保持不变。
- 下一交易日首轮扫描预算内等待执行，完成后正常进入执行阶段；真实超预算仍告警。
- 长扫描日志中有扫描期间的止损事件，且 `last_stop_check_at` 持续推进；
  `active_stage` 仍显示真实扫描阶段，不能用通用心跳替代止损检查。

如需回滚，恢复部署前源码和重启脚本并重启 Auto 服务，再核对锁与心跳。
旧版本含已知暂停自锁缺陷；回滚后保留安全暂停，等待重新修复，不强制恢复交易。
