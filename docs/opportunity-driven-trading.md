# 机会发现、动态风格与独立复盘

## 模拟盘资金轮次

新账户和CLI的默认初始资金为10万元。修改默认值不会重置已有账户；已有模拟盘必须
显式归档后开启新轮次，不能仅把100万元净值改小而沿用旧的回撤峰值。

维护时先停止Auto及所有数据库写入任务/定时器，确认无持仓后执行：

```bash
BROKER_MODE=paper python scripts/start_paper_round.py --db /path/to/data/quant.db \
  --capital 100000 --round-id paper-100k-20261009 --workers-stopped
```

脚本在私有`data/round_archives/<round-id>/`保存数据库、WAL/SHM及一致性备份，归档旧
成交、复盘、决策、信号与账户运行状态，再初始化10万元现金、零持仓、零盈亏和新回撤峰值。
市场K线、市场状态历史和独立教训保留；人工暂停状态不变。相同轮次ID重复运行不会再次重置资金。
当晚标记不自动重放复盘，次一交易日正常开始。归档不得提交Git或公开。

若维护失败，保持写入任务停止，核对归档manifest与账户状态；恢复时使用一致性备份
和对应runtime文件，不能混用新旧数据库/JSON。验证资金、回撤与数据库完整性后再恢复服务。

## 运行流程

`行情与候选数据校验 → 低位/事件/放量候选 → 量化评分与入场资格 → 动态风格提示 → 大模型判断 → 独立硬风控 → paper 执行 → 成绩审计 → 复盘角色生成次日计划`

交易员的目标是在风险预算内发现扣费后有优势的机会，兼顾错误入场和踏空成本。
风格覆盖趋势跟随、突破回踩、区间波段、超跌反弹、事件驱动和防守。
候选池不再启用会屏蔽龙虎榜、放量来源的纯低位模式；已有低位来源保留。
缓存候选池在正常刷新后才反映来源变化，不因提示词更新立即重建。

T+0只适用于执行链路已有元数据许可的证券，当前个股提示读取持仓的 `allow_t0`。
普通A股新买入当日不能卖出；可转债仍走既有独立交易路径。本次没有新增套利执行器，
也不把波动机会称为无风险套利。

## 动态提示与职责

- 固定系统层：机会发现目标、数据边界、交易制度、硬风控不可覆盖。
- 动态状态层：北京时间、市场状态、持仓买入日期、持仓天数、分项指标定义、当前策略。
- 当日风格层：`style_plan.preferred_styles`、`focus`、`invalidate_when`。
- 牛市默认重视趋势和事件，震荡重视波段，反弹重视趋势确认，熊市防守并评估独立事件和反转。
- 当日复盘计划仅在 `effective_date` 等于决策日且 `regime` 匹配时使用；过期或盘中市场状态改变，
  回到当前市场的风格，不继续沿用旧状态。分析重点不代替交易资格检查。

独立复盘角色复用已有日终LLM调用，是与盘中交易员分开的提示和调用，不是新常驻服务。
它检查成绩后生成下一交易日的结构化指令；不直接重写系统提示、不修改模型权重。
旧版本指令没有 `style_plan` 仍可读取。无效新计划不覆盖上一个有效指令。
证据不足时沿用现有入场门槛/仓位约束，不把“多交易”当改进目标。

系统与用户提示完整保存在内部 `llm_prompt`，动态风格携带 `prompt_version=opportunity-v1`。
提示词仍不在生产公共页面暴露。历史记录没有模型身份或完整输入的缺口不能追溯补造。

## 成绩和踏空审计

`strategy/decision_audit.py` 将空仓HOLD与持仓、T+1、失败、BUY/SELL信号、实际成交分开。
同日同股重复判断只取最后一次有效理由。窗口选择最近10个有模型决策的日期，
不能等同于最近10个自然日或完整市场交易日覆盖。

审计假设次日开盘入场，分别在判断后的第3、第5个交易日收盘退出，扣除默认0.21%的双边
费率和滑点假设。最大上涨空间从假设买入的下一交易日起计算，避免普通A股T+1下将
买入当日高点当作可卖价。最低价包含买入当日，以观察锁仓期间风险。

这只是日线反事实：没有盘口和完整成交模拟，涨跌停/停牌可能不能成交；不能用最高价
宣称可获得收益，也不能将同股跨日样本视为独立试验。缺窗口内任何一个交易日日线都不
算成熟，不用“第N根现有日线”替代第N个交易日。未成熟样本单列。

已有数据库日线可能是盘中快照或停止更新。自动复盘的审计标记 `unverified_daily_bars`
或 `missing_reference_calendar`，不把未经核验的数据作为策略晋级证据。
独立评估角色可以指出覆盖缺口和提出分析假设，但不能声称已提升净收益。

手工只读核查可使用公开不复权日线，输出到忽略跟踪的本地报告目录：

```bash
python scripts/audit_hold_opportunities.py --db /path/to/quant.db --as-of 2026-10-09 \
  --sessions 10 --public-prices --output data/reports/hold-audit-2026-10-09.json
```

不传 `--public-prices` 时只读取本地数据库。命令不调用LLM、不回填数据库、不下单。
`--as-of` 应指定已收盘日期。

复盘中已平仓买入按 `trade_id` 去重并限制日期；SELL不因为平仓亏损被当作选股失败。
`risk_exit` 的经济结果保留，退出来源另行解释。历史 `outcome_pct` 仍是价格涨跌幅，
不冒充完整扣费收益。评估模型只能补充文字建议，不能覆写代码计算的成绩。

## 验证和回滚

离线测试覆盖风格过期/状态切换、T+0权限、旧指令兼容、候选来源、完整提示留存、
重复扫描去重、T+1峰值、缺失行情、复盘不能改写统计，以及现有交易风控。
不需要新增依赖或数据库迁移。部署后需要单独检查真实请求、候选源耗时、计划生效日期与
实际模型身份；本地测试不证明交易盈利或线上运行通过。

回滚只恢复本次提示、风格/审计接线与候选来源修改，保持其他在途修改。
新指令额外的 `style_plan` 字段不改变原参数；旧代码忽略它。持续保持 `BROKER_MODE=paper`。
