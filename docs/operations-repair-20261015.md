# 复盘闭环与前向研究运行修复

保持 `BROKER_MODE=paper`，公网控制接口仍关闭。修复不把新增因子模型晋级为交易策略。

## 决策与复盘

- Watchdog 从数据库检查未解决复盘，跨日、休市日仍保留 critical。已生效但非当日的策略明确标为过期；计划生成及执行均禁止用旧策略新开仓。
- 策略生成使用独立 JSON 调用，只接受完整 `content`，拒绝截断响应；日志保留结束原因、长度和内容哈希。
- 自动循环只重试明确为“AI明日策略指令未完成”的失败步骤。必须有已保存文字复盘，不能有其他并列错误；最多三次，间隔十五分钟，仅盘后和生效日 09:25 前运行。不重放教训、订单、净值快照。其他部分失败仍需核对。
- 每日事实按整天持久化信号汇总零置信度维度，LLM无响应单独计数并按扫描/股票去重，不计入主动HOLD。
- 沪深300使用明确的 `sh000300` 指数日线，缺报价返回未知。累计链缺口可用同一起点的已核验指数端点重算，不能延续旧值伪装当日收益。
- 信号参考价使用判断前取得、通过代码和时间校验的实时报价；保留日线价格用于审计，执行时继续使用原有双向漂移保护。

## 独立前向任务

`scripts/run_forward_jobs.py --config CONFIG.json` 在配置的冻结源码目录加载模型，使用固定依赖、独立 SQLite 状态和公开行情；一份采集快照供六模型与原60特征两项实验。

配置字段为 `runtime_root`、`factor_state`、`ml_state`、`calendar`、`snapshot_root`、`health_file`，均使用绝对路径。进程锁串行任务，结果原子写入健康文件；原状态库仍执行指纹、真实日期、历史修订和漏日门禁。

`scripts/install_forward_research.py` 生成 systemd 用户单元，显式 `--install` 才安装。北京时间工作日16:20运行，17:20、20:20及次日08:30提供有限重试；单次最长50分钟、CPU上限一核、内存上限3GB。服务不读取交易账户凭据。

旧六模型实验因跨供应商历史修订中断，旧ML实验因漏日中断，均保留原库。新实验于2026-10-15开盘前用14日收盘快照登记，重新观察60个新交易日，不能拼接旧收益。

旁路LLM比较在实现变化时另建关联实验，旧实验归档保留。`scripts/refresh_research_input.py` 使用已核验原始独立日历和本地行情；原价、真实涨跌停、交易状态及公司行动证据未齐时仍返回 `waiting_execution_data`。采集与调度成功不等于已有严格收益结果。

## 验证与回滚

必须通过 Watchdog、Doctor、自动循环、公网接口、策略指令、报价/执行、复盘事实与新增调度回归，再重启。核对未解决领取、当日指令日期、研究指纹、任务退出码和下次触发时间，不能只看服务active。

部署前备份覆盖的源码、用户单元、复盘文件和SQLite一致性快照。回滚源码只恢复本次覆盖的文件；新增研究任务可用 `systemctl --user disable --now alpha-pilot-forward-research.timer` 停止。保留实验状态与失败快照；不要以恢复旧账户数据库作为一般代码回滚手段，也不要重新执行已有计划。
