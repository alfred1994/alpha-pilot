# 模拟盘可靠性约定

更新日期：2026-08-21
执行者：Codex

## 账户与成交

- 系统仅支持 `BROKER_MODE=paper` 的模拟盘运行。
- 买入和卖出会拒绝零值、负值、非有限数以及不符合整手约束的输入。
- 普通 A 股在模拟账户最终成交边界执行 T+1：买入当日的 LLM 卖出、止损和其他卖出入口都会被阻断，且不会改变现金、持仓或成交记录。
- T+0 不按证券代码或名称自动推断；只有上游证券元数据明确传入 `allow_t0=true` 的品种才允许当日回转，该属性随持仓持久化。
- 一笔模拟成交会在同一 SQLite 事务内同时写入账户快照、持仓投影和交易记录；SQLite 是唯一事实来源。
- 可转债订单必须由证券元数据显式标记 `allow_t0=true`，并使用10张交易单位；扫描产生的买入机会会进入 TradePlan 执行层，不再只展示不成交。
- 成交记录会保存 `signal_score`、`signal_detail`、`market_regime` 和结构化 `dimensions`，LLM 决策通过 `trade_id` 与实际成交关联。
- `data/paper_account.json` 仅是账户备份，采用临时文件加原子替换写入。数据库提交成功后即使备份失败，也不会回滚已经完成的成交。

## TradePlan 执行

- 每个 TradePlan 根据其稳定内容生成 `plan_id`，数据库会记录领取和完成状态。
- 同一计划不会因重试、进程重启或并发调用而重复下单。
- 自动执行只接受当前交易日、未超过 `deadline` 的计划；历史计划只能在显式回放场景中执行。
- TradePlan 使用计划日期计算可卖数量；被 T+1 阻断的 SELL 会在订单审计中记录 `blocked` 和具体原因。

## 市场数据与候选池

- 市场快照过期后会先进行有界刷新；刷新失败时可以保留旧快照继续观察，但 TradePlan 会记录 `source=stale_cache`、年龄和刷新错误，不再把“数据不可用”伪装成涨停/跌停数量为 0。
- 候选池默认按 30 分钟新鲜度管理。每次刷新会记录 `version`、`generated_at` 和候选数量；刷新失败时才显式回退到旧池，并在自动循环事件中记录版本变化。
- 轻量看盘优先使用同一轮 TradePlan 的综合评分；候选池过期、市场快照过期或刷新失败都会进入每日交易员简报的能力降级列表。
- ML 信号异常时保留异常维度用于审计，但从本轮综合评分中剔除其固定权重，并对剩余有效维度重新归一化；看板会同时展示降级状态和该处理结果。
- 舆情、市场快照、候选池等任一数据源降级都会进入 LLM 的数据质量上下文；置信度为零的维度不参与综合评分。
- 市场环境标签采用置信度迟滞：低置信度的单日反转沿用上一交易日标签，原始判断会保存在指标中供审计。
- 常驻自动循环的周期报告只通过统一日志通道输出一次，避免服务日志同时记录 logger 与标准输出造成重复膨胀；运行脚本仍保留 20MB 单文件轮转。
- 日线缓存会校验最新日期；明显落后的缓存会触发 Longbridge/Baostock 补拉，外部数据源失败时才以带滞后标记的旧缓存降级，不能静默把历史行情当成今日行情。
- 观察池救援只对新确认或市场状态发生新变化的证据触发一次，重复的同一观察证据不会循环调用 LLM。
- 每轮 TradePlan 的候选都会写入反事实观察；盘后基于已落库K线回填 1/3/5/10 日收益及 5 日 MFE/MAE，用于区分正确观望、错过机会和错误买入。该数据只用于学习和影子评估，不改变当日下单。
- 东方财富浏览器请求统一复用一个专属事件循环和一个 CloakBrowser 主实例；页面逐次关闭，空闲20分钟后关闭浏览器。Watchdog按浏览器主实例而不是 renderer 子进程计数，只告警、不终止进程。
- `--research-sync` 只在盘后运行，研究池默认上限800只高流动性普通A股，显式排除ETF、指数、北交所和科创板；每批默认8只、固定串行、900秒总上限，失败标的进入重试队列，不参与当日交易。Linux任务安装后会在工作日19:10自动触发。
- `--train-pooled-model` 只在研究数据同步之后运行，按日期做 purge/embargo 样本外验证；覆盖、AUC、平衡准确率、基线增益或Brier不达标时保持 `blocked`，失败报告不会覆盖上一份仍合格的影子模型，也不会改变正式交易。
- 每次扫描的候选作为独立反事实观察保存；同一计划重试保持幂等。盘后逐步回填扣除比例费用与滑点后的1/3/5/10日收益，T+5完整后才生成MFE/MAE和正确HOLD、错误HOLD、正确BUY、错误BUY标签。
- 六个影子策略变体（baseline/loose_top/strict_top/ml_heavy/ml_none/ml_only）每轮扫描共享同一份打分推导决策并落库，不重复访问外部接口；指标用 T+5 净收益反事实回填计算，错误HOLD率=持有且后续5日上涨的比例。
- 影子晋级只产生候选（shadow_promotions status=candidate，门槛：≥20交易日且≥10笔已回填买入、净收益超baseline 0.5%且胜率不低），应用候选必须人工确认；旧 A/B 实验 running 超14天自动标记 expired。

## 回测口径

- 信号使用前一交易日已收盘数据，成交发生在下一交易日。
- A 股普通股票默认执行 T+1 卖出限制。
- 佣金、最低佣金和卖出印花税由持仓管理器统一计算，并计入现金和交易记录。
- 回测结束使用最后可得价格估值，不通过强制平仓绕过交收限制。

## Web 看板

- `GET /positions` 只用实时价格计算本次响应，不修改账户、持仓或数据库。
- `GET /trades` 只读取交易记录，不在查询时修复或回填历史盈亏。
- 账户读取失败会标识为不可用，不再伪造默认的一百万元账户。

## 验证与回滚

- GitHub Actions 的 `Test AlphaPilot` 工作流在干净的 Python 3.12 环境中安装依赖、执行依赖检查、编译和回归测试。
- 回滚代码时应一并回滚相应数据库变更；新增表 `trade_plan_executions` 保留历史执行审计，不包含账户密钥或凭据。
- 发生账户数据异常时，先停止自动执行，再备份 SQLite 文件后使用交易记录和账户快照核对，不要手工修改公开看板接口来“修复”数据。
