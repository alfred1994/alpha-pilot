# 架构审计逐项核实：风险、账户与数据

核查日期：2026-09-28。以下结论依据当前工作树源码和离线回归；原审计文档中的生产活数据计数未重新读取或复现。`BROKER_MODE=paper` 保持不变。

## A 域

- **A1 成立。** 原 `system_risk.py` 与 `drawdown.py` 直接截断写 JSON，损坏读取保留放行默认值。现使用跨进程文件锁与同目录临时文件原子替换，损坏状态抛异常，账户纸单门禁拒绝成交。风险文件损坏回归已加入。
- **A2 部分成立。** 同日记录只检查末项，旧状态副本整份覆盖确实会重复或丢数据。审计列出的生产日期计数属于历史观察，此次未碰生产文件。更新前在锁内重读、同日去重并重算日盈亏；较旧日期不能覆盖新记录。`forbid_new_buy` 仍按触发当天禁买，次日自然失效，原审计关于“次日禁买”的文案与既有执行语义冲突，未据此改变交易规则。
- **A3 部分成立。** 历史高水位是历史回撤的正常定义，不能每日重置，否则会弱化最大回撤控制。账户文件路径隔离已有实现；本次保留高水位，修复 `preview` 临时替换 `self.state` 的线程安全问题，并使文件更新先锁后重读。跨账户共享默认状态的风险由调用方账户目录隔离，具体生产配置仍需核验。
- **A4 成立。** 编排原先不带现价调用 `total_assets()`，盘中浮动盈亏被低估；成交后也不复评。编排修复由 orchestration 负责：要求新鲜持仓报价完整覆盖、按价格估值及成交后更新风险。账户买入持仓非空时若缺 `prices` 映射会拒绝纸单。
- **A5 成立。** 两控制器默认用宿主本地日期，编排只给回撤控制器显式日期。风险控制器默认改用北京时间，编排统一传计划日期。
- **A6 部分成立。** `PaperAccount` 原只做持仓数、单票比例、T+1、手数，系统级暂停、回撤和日亏由编排掌握。账户纸单边界现读取同账户风险/暂停状态，损坏时拒绝交易；连亏降仓作为目标仓位缩放仍由编排计算。**行业 ≤2** 的函数确实无调用，但 `docs/TODO.md` 明确行业字段尚不可信，此项属于未完成的研究能力，不能从代码/名称猜行业后强制限制。`trigger_system_halt` 无生产调用方仍是观察到的接线缺口，未凭空新增触发事件。
- **A7 成立。** 账户写事务只能保证单次原子性，旧内存快照会覆盖新现金/持仓。`account_state.version` 配合 `BEGIN IMMEDIATE` 检测旧版本并拒绝写入；交易及非交易状态保存均使用该版本，失败时内存回滚。直接管理 API 仍可用于显式重建/迁移，常规账户写路径使用 CAS。
- **A8 成立。** 原暂停只在自动循环部分分支检查。账户纸单买卖现在读取控制状态，所有经 `PaperAccount` 的入口统一受控；历史回放需显式 `execution_context='replay'`。账户外的其它交易通道仍须单独审核。
- **A9 成立。** 原两个 `is_*_allowed()` 会清理并写状态。现判断只读，更新由显式 `update()` 路径负责。
- **A10 成立。** 原 `timedelta(days=N)` 可使周五熔断在周末到期。现按交易日推算排他恢复日；期限届满后若历史回撤仍超阈值，继续禁交易至净值恢复或人工复核。日历不可得时不会开放未知日期交易。
- **A11 部分成立。** 原执行层完全没有涨跌停/停牌判断。现在有实时报价的纸单校验代码、时间、价格、成交量与可得的板价；ETF/转债缺可信板价时禁止新买，风险卖出在新鲜且有成交量的报价下继续模拟，并明确记录成交可行性未知。普通股票仅在有昨收且交易板规则可确定时估算限价；名称不能覆盖所有 ST/新股例外，因此真实撮合与排队成交仍未模拟，纸单不得被解释为真实可成交证明。
- **A12 成立。** 原单票上限按旧持仓价估值。账户买入接受完整新鲜价格映射重算上限；有持仓却缺映射时拒绝纸单。编排负责传同批验证过的报价。
- **A13 混合。** `check_stop_conditions` 原忽略 `shares`，已传给 `sell`；T+1 禁卖是正确结算约束，原止损未成交无明确日志，现记录重试告警。`drawdown.py __main__` 演示已改为临时目录。`main.py --stop-check` 报价校验由 orchestration 负责，不能用本模块测试替代主入口验证。

## B12 与 D 域

- **B12 部分成立。** 原每次 `Database.__enter__` 都执行 schema 创建/探测；审计把每条语句称为独立隐式写事务并直接断定是锁的主要来源，没有运行时锁证据。现按 SQLite `user_version` 仅在首次/升级时串行迁移，常规打开不跑全量 DDL；只读连接使用 `mode=ro` 和 `query_only`，不建库、不迁移。
- **D1 成立。** Windows 直接调用 Baostock 丢弃超时；现 Windows 用 `spawn` 子进程，超时终止。离线回归子进程从 `ALPHAPILOT_OFFLINE_TEST` 标记拒绝真实 provider 调用，避免绕过主测试进程审计钩子。
- **D2 成立。** 原 `get_daily` 以 `attrs` 标陈旧缓存，而技术打分、组合回测、快速回测、Qlib 信号和 `stock_picker` 没有统一检查。现在共享 `daily_history_usable()` 拒绝陈旧结束端、严重内部缺口及无起点解释的稀疏窗口；晚上市造成的起点缺口可以继续研究。编排技术打分已接自身覆盖检查；组合回测、快速回测、Qlib 信号及 `stock_picker` 已接共享检查。回测以显式请求结束日判断，不要求历史样本截至今天仍新鲜。
- **D3 成立。** 同键 `INSERT OR REPLACE` 可让 KT 空字段覆盖完整行，也会让后来的降级源覆盖 OHLC。现在更新保留已有非空字段，已有完整非 KT 行不被 KT 覆盖。缓存仍只允许 `qfq`，复权维度仅由调用方保证，未来多复权缓存需要 schema 扩展。
- **D4 成立。** 熔断自然日已改交易日。表外年份在 Baostock 不可用时原把全部工作日视为交易日；现返回无可信交易日，`next/prev_trading_day` 在 30 天内无结果时抛错，避免节假日误交易。
- **D5 部分成立。** `candidate_outcomes` 逐扫描增长且无清理；其性质是业务/训练样本，现有维护策略明确不自动清理业务训练数据。原文按“5 仓 × 扫描次数”估容量与真实候选数不相符，未测实际库体积。保留数据，由备份/容量监控决定归档策略；不在本次静默删除训练样本。
- **D6 部分成立。** 裸 `sqlite3.connect` 不重复发 `PRAGMA journal_mode=WAL` **不构成 WAL 配置不一致**，WAL 是数据库文件持久属性。原单笔大 `DELETE` 可持写锁，现运维日志按 500 行分批提交；完整性/备份仍用 SQLite 官方连接接口。库无 `FOREIGN KEY` 约束属实，当前 `foreign_keys=ON` 和 `foreign_key_check` 不证明跨表一致性；补真实外键需另定已有孤儿数据迁移契约。
- **D7-1 部分成立。** `positions` 是账户投影，原缺 `allow_t0`、买入 ATR 与价格更新时间；现新增列并同步，旧行需通过账户快照再次投影才能填充新增元数据。审计称“无迁移机制”过于绝对，原有若干增列/保存点迁移，只是缺有序版本；已增加 `user_version`，仍未形成完整迁移列表。
- **D7-2 成立。** `data.rate_limit` 线程无锁、睡眠后更新；现用锁和单调时钟串行保留调用间隔。
- **D7-3 部分成立。** 跨源 K 线无逐值对账与异常阈值确属缺口；日线覆盖/有限值验证与执行报价验证已存在。此次补来源覆盖保护，不声称完成跨源对账。
- **D7-4 成立并由其他代理修复。** `realtime/event_bus.py` 原未启动 loop 时事件入错队列、关停残留队列，当前修复由实时模块代理负责，验收需看其专项回归。
